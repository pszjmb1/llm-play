## User Acceptance Testing Guide for Edge Function Submission Handling

# Overview

This guide outlines how to verify that the MVP Submission Handling via Edge Functions (Issue #14) is working correctly. The feature provides a
streamlined API for environment submissions with validation, database storage, and job queuing.

# Prerequisites

- Access to the LLM-Play development environment
- Valid authentication credentials (for authenticated tests)
- Postman, cURL, or another API testing tool

# Test Cases

## 1. Basic Environment Submission

Objective: Verify that a valid environment can be submitted via the edge function.

### Steps:

1. Send a POST request to /api/edge-submit with a valid payload:
   {
   "name": "Test Environment",
   "description": "This is a test environment for Edge Function submission",
   "metadata": {
   "environmentType": "text-game",
   "difficultyLevel": "medium",
   "tags": ["test", "edge-function"],
   "successCriteria": "The environment should process the submission correctly"
   }
   }
2. Verify the response:

   - Status code: 200
   - Response contains success: true
   - Response includes environment details with an ID
   - Response includes job details with "queued" status

### Expected Result

Environment is created in the database and a job is queued.

## 2. Submission with File URL

Objective: Verify that a submission with a file URL is processed correctly.

Steps:

1. Upload a file using the existing file upload API
2. Use the returned file URL in a submission:
   {
   "name": "File Test Environment",
   "description": "This tests file URL processing in submissions",
   "file_url": "[URL from previous upload]",
   "metadata": {
   "environmentType": "code-generation",
   "difficultyLevel": "medium",
   "tags": ["test", "file"],
   "successCriteria": "The environment should store the file URL correctly"
   }
   }
3. Verify the response includes the file URL in the environment details

### Expected Result

Environment is created with the file URL correctly stored.

## 3. Validation Error Handling

Objective: Verify that invalid submissions are rejected with appropriate error messages.

Steps:

1. Send a POST request with an invalid payload (missing required fields):
   {
   "name": "",
   "description": "Too short"
   }
2. Verify the response:

   - Status code: 400
   - Response contains validation error details
   - Response includes specific error messages about the missing/invalid fields

### Expected Result

Request is rejected with validation errors.

## 4. Authentication Requirement

Objective: Verify that authentication is required for submissions.

Steps:

1. Send a POST request without authentication credentials
2. Verify the response:

   - Status code: 401
   - Response contains authentication error

### Expected Result

Request is rejected with authentication error.

## 5. Complete End-to-End Flow

Objective: Verify the complete submission flow from the UI.

Steps:

1. Log in to the LLM-Play application
2. Navigate to the environment submission form
3. Fill in all required fields including uploading a test file
4. Submit the form
5. Verify that:

   - Success message is displayed
   - Environment appears in the user's environments list
   - Job status is shown as "queued"

### Expected Result

Environment is successfully submitted through the UI with all data correctly saved.

## Performance Testing

Objective: Verify that the edge function provides improved performance.

Steps:

1. Use a tool like Apache Benchmark to send 50 concurrent requests
2. Compare response times with the standard API route
3. Verify that cold start times are acceptable

### Expected Result

The edge function should have similar or better average response times compared to the standard API route, especially for users in different geographic regions.

## Documentation Verification

Objective: Verify that documentation is complete and accurate.

Steps:

1. Review the ADR-0004 document to ensure it accurately describes the implementation
2. Check the edge functions guide for completeness and correctness of usage examples
3. Verify that any API changes are documented in the developer documentation

### Expected Result

All documentation is complete, accurate, and consistent with the implementation.

# Reporting Issues

If you encounter any issues during testing:

1. Take screenshots and record the exact steps to reproduce
2. Note any error messages or unexpected behavior
3. Report the issue with details about your environment (browser, OS, etc.)
4. Submit the issue to the project's issue tracker with the tag "edge-function"
