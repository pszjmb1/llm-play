# [ADR](<https://github.com/pszjmb1/llm-play/wiki/Architectural-Decision-Records-(ADRs)>)-0003: Environment Execution Options

## Context

For LLM-Play to function effectively as a research platform, we need to determine how researchers will execute environments against various language models. This decision impacts platform architecture, security, usability, and research flexibility. There's a tension between accessibility (running everything on our platform) and flexibility (allowing researchers to run locally against proprietary models).

Business drivers include:
- Making the platform accessible to researchers without requiring technical setup
- Supporting evaluation of proprietary, local, or unreleased models not accessible via API
- Ensuring security when executing community-contributed code
- Maintaining reproducibility and standardization of results
- Balancing server costs against platform usability

## Decision

We will implement a hybrid approach with two primary execution modes:

1. **Cloud-Hosted Execution** (Primary Option):
   - Environments run directly on the LLM-Play platform through a web interface
   - Execution occurs in sandboxed environments with resource limits
   - Supports integration with popular LLM APIs and researcher-provided API keys
   - Results automatically stored and visualized on the platform
   - Standardised I/O interfaces ensure consistent evaluation

2. **Downloadable Packages** (Secondary Option):
   - Environments available as standardized, downloadable packages
   - Researchers can run locally against proprietary or air-gapped models
   - Results can be optionally uploaded back to the platform
   - Digital signatures ensure package integrity

The system will maintain a consistent results format regardless of execution location to enable comparison and aggregation of findings.

## Business Value

This hybrid approach delivers value by:

- **Broader Adoption**: Low-barrier cloud option encourages new users while downloads support advanced researchers.
- **Research Diversity**: Enables testing against a wider range of models, including proprietary ones.
- **Cost Efficiency**: Researchers can offload computation-intensive evaluations to their own infrastructure.
- **Data Collection**: Standardized results format creates a valuable dataset for meta-analysis.
- **Security**: Sandboxed cloud execution protects platform while still allowing community contributions.
- **Competitive Advantage**: Flexibility differentiates from platforms that only support specific models or execution methods.

## Consequences

### Positive
- Supports both casual users and advanced researchers
- Enables evaluation of proprietary or specialized models
- Distributes computational load between platform and researcher resources
- Maintains standardization through consistent interfaces
- Increases total number of evaluations possible on the platform

### Negative
- Increased development complexity to support both modes
- Potential for divergence in results between cloud and local execution
- Additional security considerations for downloadable code
- Need to maintain compatibility across multiple execution environments
- More complex documentation and onboarding

## Alternatives Considered

1. **Cloud-Only Execution**
   - Rejected as it would limit testing to only publicly available models and create scaling challenges

2. **Download-Only Approach**
   - Rejected as it creates too high a technical barrier for many potential users

3. **API-Based Execution Without UI**
   - Rejected as it would exclude non-technical researchers and reduce platform usability

4. **Third-Party Execution Providers**
   - Rejected due to dependency risks and potential cost issues

## Effort Estimation

- **Time**: 
  - Cloud execution: 1-2 months (priority implementation)
  - Downloadable packages: 2-3 additional months
- **Resources**:
  - Backend developer with security expertise (1 FTE)
  - DevOps engineer (0.5 FTE)
  - Frontend developer (0.3 FTE)
  - Technical writer (0.2 FTE)
- **Complexity**: High
  - Security concerns with executing user code
  - Ensuring consistency between execution environments
  - Managing computation resources
- **Dependencies**:
  - Completion of environment validation system
  - Sandboxed execution infrastructure
  - Standardized environment interfaces
- **Risks**:
  - Security vulnerabilities in sandboxed environments
  - Scalability issues with cloud execution
  - Divergence between local and cloud execution results

## Status

Proposed
